# 公众号配图规范（WeChat spec）

上游 diagram-design 的排版是给桌面宽屏设计的：12–13px 字号 / 1000 单位宽的 viewBox。
直接搬到公众号正文里，**手机上会看不清**。这份规范把它压成公众号能用的尺寸。

## 为什么（实测数据）

微信正文图片在 iPhone 上实际显示宽度约 **340 CSS px**（375 宽屏，正文左右内边距各 ~17px）。
图里 1px 只有 0.315 个 CSS px。所以：

| 图 | 图片宽 | 图内最小字 | 手机端等效 | 能用吗 |
|---|---|---|---|---|
| 上游原版（1000 viewBox / 2000 PNG） | 2000 | 24px | **4.1 CSS px** | ❌ |
| 公众号版（1080 viewBox / 1080 PNG） | 1080 | 32–60px | 10.1–18.9 CSS px | ✅ |
| 本项目现有 AI 配图叠加标注（基线） | 1312 | 57px | 14.8 CSS px | ✅ |

正文正文字号是 16–17 CSS px。**图里的字不能比正文小**，所以：

## 尺寸规范

- **viewBox 宽 = 1080**，高度 540 / 640 / 760（扁横幅，最好像一张配图而不是一屏 PPT）
- **导出 PNG 宽 = 1080**：`export_png.py <in> <out> 1`（scale=1）。不要用 scale=2，宽图会让字相对变小
- 高度 < 1080，避免手机上下滑动时被裁切感

## 字号规范（单位：1080 宽图里的 px）

| 角色 | 字号 | 手机端等效 | 说明 |
|---|---|---|---|
| 标题 | 60 | 19 CSS px | 一句话，不要超过 16 个字 |
| 副标题 / 结论 | 44 | 14 CSS px | 可选，一行 |
| 关键数字 | 48–56 | 15–18 CSS px | 这张图的主角 |
| 节点标签 | 40 | 12.6 CSS px | **下限**，一个字都不能更小 |
| 次级标注 | 40 | 12.6 CSS px | 没有 40 就删掉这句话，不要缩字号 |

汉字下限 **40px**（上游是 12px / 1000 宽，换算过来就是这个数）。
数字和汉字一样用 40px+，不要用小一号的 "单位" 脚注——删掉更干净。

## 密度规范

- **数据元素（条 / 节点 / 时间点）≤ 4 个**。上游允许 24 个，那是给 PDF/PPT 的
- **文本节点 ≤ 10 个**：标题 1–2 + 每个数据元素最多 2 处（标签 + 数字）
- 流程图最多 3 个节点，用箭头连
- **强调色（coral #bf4520）≤ 2 处**（沿用上游规则）
- 一张图讲一件事。讲两件事就拆两张
- 能用数字说清楚的事，不要写成句子

## 中文排版

- 字体栈：`'Microsoft YaHei', 'PingFang SC', 'Noto Sans SC', sans-serif`
  （PNG 是位图，读者用什么机器打开不影响结果；微软雅黑 Windows 必装）
- **汉字不要用 mono 字体**：Geist Mono 没有汉字，会掉进 fallback 导致宽度错乱
- 数字也用同一个无衬线栈，别混用 mono —— 避免不同机器渲染宽度不一致
- 不用衬线（宋体）排汉字：正文标题用黑体系更干净
- 汉字按 1em/字预算宽度；全角标点（，。：（））也占 1em
- 不要 `letter-spacing`、不要 `text-transform: uppercase`（对汉字无意义且会拉宽）
- 标签不要竖排、不要字距压缩

## 配色（沿用上游 editorial palette）

| token | 值 | 用途 |
|---|---|---|
| paper | `#f5f5f5` | 背景 |
| ink | `#2d3142` | 主文字、节点描边 |
| muted | `#4f5d75` | 次要文字、网格线 |
| accent | `#bf4520` | 强调，≤2 处 |

不要阴影、不要渐变、不要圆角超过 10px、不要 emoji。

## 工作流

1. 选段落：只挑**含具体数字**的段落。纯概念段落交给 AI 配图（`baoyu-image-gen`）
2. 定类型：条形对比 / 流程 / 漏斗 / 时间线 / 嵌套结构 / 瀑布（见 `references/type-*.md`）
3. 抄 `assets/examples/` 里最接近的一张，改内容和文案
4. 校验：
   ```bash
   python scripts/self_check.py <file.html>              # 契约：viewBox、单文件、越界
   python scripts/check_layout.py <file.html> --min-han 40  # 几何：文本重叠、出框、汉字 < 40px
   ```
5. 导出：
   ```bash
   python scripts/export_png.py <file.html> <out.png> 1
   ```
6. 放图：写到 `${输出目录}/images_good/diagram_01.png`，在文章里插 `[[IMG: images_good/diagram_01.png]]`

## 校验脚本

`scripts/check_layout.py` 用 Playwright 量每个 `<text>` 的实际 bbox，报告：

- 文本出框（超出 viewBox）
- 文本互相重叠
- 汉字字号 < 12px（上游规则的兜底；本项目公众号规范要求 ≥ 40px/1080 宽，所以还要自己扫一眼字号）

`scripts/self_check.py` 是上游自带的契约检查（远程资源、可执行属性、viewBox 越界、文件截断），保留它。
